# Android (Google Play)

The same Expo app ships to Google Play as `com.smartie.driver`. `/android` is
generated by `expo prebuild` and gitignored; everything that has to survive a
regenerate lives in `app.json` and `plugins/withAndroidRelease.js`.

## Toolchain (no Android Studio needed)

```bash
brew install openjdk@17 android-commandlinetools
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
export ANDROID_SDK_ROOT=$ANDROID_HOME
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export PATH=$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH
```

SDK packages and the `maestro_test` emulator: see `.maestro/README.md`.

## Build

```bash
npx expo prebuild -p android --clean --no-install   # after app.json / plugin / native dependency changes
echo "sdk.dir=$ANDROID_HOME" > android/local.properties
npm run bump:android                                 # before every Play upload
npm run build:android                                # → android/app/build/outputs/bundle/release/app-release.aab
cd android && ./gradlew assembleRelease             # an installable APK for the emulator
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

A clean release build takes about 15–20 minutes on this Mac. The universal APK
is ~120 MB (every CPU architecture); Play serves each device a split of the
bundle, which is much smaller.

`plugins/withAndroidRelease.js` also copies the app icon to
`res/drawable/splashscreen_logo.png`, which the splash theme references but the
splash plugin never generates; that used to be a manual step after prebuild.

## Upload key (keep it safe)

Play uses **Play App Signing**: Google holds the key that signs the app on the
Store; we sign uploads with an *upload key*.

- Keystore: `~/.config/driver-sk/driver-upload.jks` (alias `driver-upload`),
  created 29 Sep 2026 for Smartie s.r.o.
- Password and paths: `~/.gradle/gradle.properties`
  (`DRIVER_UPLOAD_STORE_FILE`, `…_STORE_PASSWORD`, `…_KEY_ALIAS`, `…_KEY_PASSWORD`).
  Without them, release builds fall back to the debug key (fine for the
  emulator, rejected by Play).
- **Back up the .jks and its password** (password manager). A lost upload key
  can be reset through Play support, but it takes days.

## Platform differences in the code

- Purchases (`src/lib/purchases.ts`): RevenueCat with the Google Play key
  `GOOG_KEY` (or `EXPO_PUBLIC_REVENUECAT_ANDROID_KEY`). While it is empty,
  Android has no paywall and everything is free, as before.
- Promo codes: Google Play has no in-app code sheet. "Redeem a promo code"
  opens `https://play.google.com/redeem`; when the user returns, the app asks
  RevenueCat to sync purchases.
- Back button / back gesture: during a drive it asks before ending the drive,
  like the on-screen back; in the drive review it goes to the practice hub.
- Notifications use the channel `study-reminders` ("Study reminders", localised).
- Outlined and secondary buttons have no shadow on Android: Android draws a
  shadow through a translucent background as a lighter box inside the button.
- The driving game draws its route hints with plain views instead of an
  animated SVG (`components/game/RouteHint.android.tsx`), Reanimated applies
  transforms synchronously (`ANDROID_SYNCHRONOUSLY_UPDATE_UI_PROPS` in
  `package.json`, compiled into the native build), and `patches/` removes
  react-native-svg's per-element Android layout events. The reasons and the
  measurements are in `docs/game/performance.md`, section "Android".

## Dependency patches

`patch-package` runs on `postinstall` and applies `patches/*.patch` to
`node_modules`. The only patch is Android-only:
`react-native-svg+15.15.5.patch` stops `VirtualView.setClientRect` from
dispatching a `topSvgLayout` event for every SVG element it paints (nothing in
the app listens to `onLayout` on SVG elements). After bumping react-native-svg,
re-apply the same change and regenerate the file with
`npx patch-package react-native-svg --include 'android/src/main/java/com/horcrux/svg/VirtualView\.java'`.
The iOS sources of the package are untouched.

## Measuring the driving game on the emulator

The emulator's GPU goes through a GL-to-Metal translation, so GPU and swap
timings are not meaningful; CPU work on the UI thread, the RenderThread's
sync (texture uploads) and the JS thread are. The app is AOT-compiled first so
Java frames are neither interpreted nor JIT noise
(`adb shell cmd package compile -m speed -f com.smartie.driver`, which Play
does through profiles on real phones).

```bash
adb shell "sqlite3 /data/data/com.smartie.driver/files/SQLite/driver.db 'update settings set has_finished_guide=1'"   # needs adb root
adb shell am start -W -a android.intent.action.VIEW -d driver://crossing com.smartie.driver   # a practice drive that cruises by itself
adb shell dumpsys gfxinfo com.smartie.driver reset; sleep 12
adb shell dumpsys gfxinfo com.smartie.driver framestats       # jank counts, percentiles, per-frame UI/RenderThread times
cat perfetto.cfg | adb shell "perfetto -c - --txt -o /data/misc/perfetto-traces/drive.pftrace"   # gfx, view, sched; analyse with the perfetto Python package
adb shell simpleperf record -p $(adb shell pidof com.smartie.driver) -e cpu-clock -f 1000 --call-graph dwarf --duration 12 -o /data/local/tmp/perf.data
adb shell simpleperf report -i /data/local/tmp/perf.data --tids <ui tid> --children --sort symbol   # DWARF unwinding attributes time to Java methods
```

## Play Console checklist (organization account, Smartie s.r.o.)

An organization account can go to production after review; there is no
12-tester / 14-day closed test requirement (that applies to new personal
accounts).

1. **Create the app**: name *Driver SK*, default language Slovak, app, free,
   contains in-app purchases.
2. **Upload a first bundle to Internal testing**. Play only lets you create
   in-app products once a bundle with the billing permission exists
   (react-native-purchases adds it).
3. **Products** (Monetize → Products), same IDs as the App Store:
   - Subscriptions `com.smartie.driver.pro.weekly` (base plan: weekly,
     auto-renewing) and `com.smartie.driver.pro.yearly` (base plan: yearly);
     each gets an offer "3-day free trial" for new customers.
   - One-time product `com.smartie.driver.pro.lifetime`.
   - Prices: EUR base, the same as the App Store (Weekly €3.99, Yearly €39.99,
     Lifetime €49.99), let Play convert the rest.
4. **RevenueCat**: add an app "Driver SK Android" (Google Play, package
   `com.smartie.driver`), upload a Google Cloud service-account JSON with
   access to the Play Console (financial data, orders and subscriptions),
   enable real-time developer notifications, import the three products and
   attach them to the `Driver SK Pro` entitlement and to the `$rc_weekly` /
   `$rc_annual` / `$rc_lifetime` packages of the `default` offering. Copy the
   `goog_…` public key into `GOOG_KEY` in `purchases.ts`.
5. **App content**: privacy policy
   (https://www.smartie.team/driver-sk/privacy), no ads, app access: no
   login, content rating questionnaire (education / reference, no
   objectionable content), target audience 16+ (not for children),
   **Data safety** (see below).
6. **Store listing** per language (sk, en, hu): texts from
   `docs/appstore/metadata.md` (short description ≤ 80 characters still to
   write), icon 512×512, feature graphic 1024×500, phone screenshots
   (2–8, portrait). Use Android captures and no iPhone frame: Play asks for
   screenshots that show the app on the platform.
7. **Internal testing → Production**.

### Data safety answers

- Data collected: *App activity* (app interactions, via PostHog, anonymous,
  optional: Settings → Analytics), *Device or other IDs* (PostHog's
  anonymous ID), *Purchase history* (Google Play / RevenueCat).
- Not collected: location, personal info, contacts, photos, messages.
- Encrypted in transit: yes. No data shared for advertising. Study data stays
  on the device.

### Promo codes on Google Play

Play Console → Monetize → Promo codes. Play supports promo codes for one-time
products (e.g. Lifetime free) and free-trial promotions for subscriptions,
with a quarterly limit on how many can be created. Users redeem them in the
Play Store (or via the app's "Redeem a promo code", which opens the Play
redeem page). Check the current limits and types in the console when
creating them; they differ from Apple's offer codes.
